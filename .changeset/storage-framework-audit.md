Security fixes from the framework audit (FA-028, FA-029, FA-033).

- **Canonical tenant segments (FA-028).** The default scope only turns a tenant id into `tenants/<id>` when it is canonical: lowercase ASCII letters, digits, `-`, `_` and inner `.` (a superset of `@basaltkit/tenancy`'s default grammar). Anything else — `Acme`, `ACME`, a decomposed or non-ASCII `é`, a trailing `.` — throws `StorageInvalidScopeError`. On a case- or normalization-insensitive filesystem (macOS APFS, Windows NTFS) `tenants/Acme` used to open `tenants/acme`, so the local driver shared a tree between two tenants that S3/GCS/Azure keep apart; now every driver behaves the same, and nothing is lowercased (that would merge `Acme` and `acme` everywhere). Apps with case-sensitive ids (nanoid, ULID) map them to a canonical segment with a custom `scope` (e.g. hex-encode the id).
- **No implicit bucket root for scoped disks (FA-029).** `onMissingScope` now defaults to `'error'` for every disk with a scope: any custom `scope` that resolves nothing, and any hand-built `new Disk()` (which cannot know whether tenancy exists). Both used to fall back to the root, where `list('')` enumerates every tenant and `get('tenants/<victim>/…')` reads another tenant's objects. The only implicit root left is a `storagePlugin` disk on the default scope in an app **without** `@basaltkit/tenancy` — single-tenant apps configured through the plugin are unchanged. `'root'` otherwise has to be asked for: `scope: null` or `onMissingScope: 'root'`. The `Disk` constructor's fourth argument (`tenancyActive`) is now optional; omitted means "unknown", not "single-tenant".
- **`copy()` cannot write into another tenant through a central disk (FA-033).** From a tenant-scoped disk, a destination disk with `scope: null` and a key inside `tenants/` (compared case-insensitively, past `.`/empty segments) throws the new `StorageCrossTenantCopyError` (`STORAGE_CROSS_TENANT_COPY`, 403). Central destinations outside `tenants/` (`backups/…`) and copies between scoped disks work as before — the JSDoc's "a copy can never write outside the tenant it runs in" now holds.

**Why major:** a hand-built `new Disk(name, driver)` and any custom-scope disk now throw `StorageTenantRequiredError` with no tenant in context instead of using the root (add `scope: null` for a central disk, or `onMissingScope: 'root'`); tenant ids with uppercase or non-ASCII characters are refused by the default scope; and a scoped → central copy into `tenants/` is refused.
